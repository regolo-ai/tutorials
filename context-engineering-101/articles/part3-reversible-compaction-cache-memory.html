Offloading large tool outputs stops sudden spikes in your context window, but it does not stop the slow, steady climb of a thirty-turn coding session. As your agent edits files, runs tests, and reads retrieved memories, the conversation history still grows until it hits the attention ceiling.

Even worse, the way most teams wire long-term memory into their harness quietly destroys prompt caching. When you search a memory store on every turn and paste the fresh hits into the top of your system prompt, the prefix changes on every message, forcing the inference engine to re-process the entire session history from scratch.

Reversible compaction: resetting the climb without losing a line

While offloading stops individual tool spikes, conversation history still climbs over a long debugging session. When token usage crosses your threshold, reversible_compact() performs three steps:

  1. Archive verbatim turns to disk: It writes the older messages to .harness/conversation_history/<session_id>.md so no code snippet, stack trace, or decision is ever permanently lost.
  2. Summarize with a lightweight model (qwen3.5-9b, routed automatically via Brick): The harness sends the older turns to brick-v1-beta, our Brick Mixture-of-Models semantic router, which detects that summarizing chat turns is a low-complexity task and dispatches it to qwen3.5-9b, condensing 2,445 tokens of history into a 195-token checkpoint.
  3. Keep recent turns verbatim: It preserves the most recent messages untouched so the agent never loses immediate context in the middle of an edit.

#!/usr/bin/env python3
"""piece3_compaction_and_cache_memory.py: Cache-safe memory layout + reversible history compaction."""
import json, os, ssl, urllib.request
from pathlib import Path

REGOLO_BASE_URL = os.environ.get("REGOLO_BASE_URL", "https://api.regolo.ai/v1")
HISTORY_DIR = Path(".harness/conversation_history")
_SSL_CTX = ssl._create_unverified_context()

def build_cache_safe_messages(system_prompt: str, always_on_memory: str, dynamic_hits: str, history: list[dict], user_msg: str) -> list[dict]:
    return (
        [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": f"[Standing Project Memory - Always On]\n{always_on_memory}"},
            {"role": "assistant", "content": "Understood. I will apply this standing project memory."},
        ]
        + history
        + [{"role": "user", "content": f"{user_msg}\n\n<retrieved_turn_memory>\n{dynamic_hits}\n</retrieved_turn_memory>"}]
    )

def reversible_compact(messages: list[dict], session_id: str, api_key: str, keep_recent: int = 2) -> dict:
    HISTORY_DIR.mkdir(parents=True, exist_ok=True)
    archive_path = HISTORY_DIR / f"{session_id}.md"
    older, recent = messages[:-keep_recent], messages[-keep_recent:]
    archive_text = "\n\n".join(f"### {m['role'].upper()}\n{m['content']}" for m in older)
    archive_path.write_text(archive_text, encoding="utf-8")

    req = urllib.request.Request(
        f"{REGOLO_BASE_URL}/chat/completions",
        data=json.dumps({
            "model": "brick-v1-beta",
            "messages": [
                {"role": "system", "content": "Summarize earlier turns into (1) completed actions, (2) key files/decisions, (3) open blockers. Max 120 words."},
                {"role": "user", "content": archive_text},
            ],
            "max_tokens": 220,
            "temperature": 0.1,
            "chat_template_kwargs": {"enable_thinking": False},
        }).encode("utf-8"),
        headers={"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"},
        method="POST",
    )
    with urllib.request.urlopen(req, timeout=45, context=_SSL_CTX) as resp:
        data = json.loads(resp.read().decode("utf-8"))
    summary = (data["choices"][0]["message"].get("content") or "").strip()
    compacted = [{"role": "system", "content": f"[CHECKPOINT - Full log at {archive_path}]\n{summary}"}] + recent
    return {"served_by": data.get("model"), "archive_path": str(archive_path), "messages": compacted}

Frequently asked questions

Why does pasting retrieved memories into the system prompt break prompt caching?
LLM inference engines cache tokens from the start of the prompt up to the first changed token. Because per-turn memory search results change on every user message, placing them inside the system prompt invalidates the entire conversation history behind them.

Where should always-on memories and dynamic search memories be placed in the prompt?
Fetch stable project or user preferences (such as AGENTS.md) once at the start of the session and place them immediately after the system prompt. Append dynamic per-turn search results at the very end of the messages array, after the current user message.

What makes compaction reversible in an agent harness, and what role does Brick play?
Reversible compaction is a harness pattern: before summarizing older messages with a compact model like qwen3.5-9b, the harness writes the verbatim transcript to .harness/conversation_history/<session_id>.md and includes that file path inside the summary checkpoint. Brick (brick-v1-beta) is our Mixture-of-Models semantic router: when the harness sends a summarization request to brick-v1-beta, Brick detects that summarizing chat turns is a low-complexity task and routes it to qwen3.5-9b instead of billing your primary frontier model.

Can I switch models on the Regolo API without losing my agent’s memory?
Yes. Because your standing memory lives in plain Markdown files and local history archives under your control, you can switch between GLM-5.2, Qwen3.8-27B, and GPT-OSS 120B on our flat Core plan while keeping the exact same memory state under European Zero Data Retention.

How much history does reversible compaction save on a multi-turn run?
In our 15-turn self-test on brick-v1-beta (served by qwen3.5-9b), reversible compaction reduced older conversation history from 2,445 tokens to 195 tokens, a 92.0% reduction with zero data loss.
