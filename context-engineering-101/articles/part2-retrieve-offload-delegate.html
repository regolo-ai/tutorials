Even after you trim your startup system prompt, a single noisy tool call can wreck an agent session in one move. Ask a coding or operations agent to inspect an audit export or a test runner log, and a naive tool will dump ten thousand tokens of raw lines directly into the main conversation history.

Once that wall of text lands in the primary context window, you pay for it twice: every subsequent turn re-processes those ten thousand tokens, and the model’s attention gets pulled toward repetitive log lines instead of your actual goal. Simply truncating the output at the first thousand characters is even worse, because the critical failure line is usually buried halfway through the file.

2. How retrieve, offload, delegate protects the main agent

Instead of returning raw text straight to your primary model (such as GLM-5.2 or Qwen3.8-27B), Piece 2 wraps your tools in a three-step contract:

  1. Retrieve pointers, not walls of text: Use glob and grep when you know the exact keyword, and call Qwen3-Embedding-8B on /v1/embeddings when searching by concept.
  2. Offload oversized tool outputs to disk: Whenever a tool output exceeds your character threshold, the middleware saves the full content under .harness/large_tool_results/ and hands the main agent only the file path plus the first five and last three lines.
  3. Delegate reading to an isolated subagent: The main agent passes the saved file path and a specific question to delegate_chunk_analyst(), which calls brick-v1-beta in a separate, disposable context window. The subagent reads all 19,643 BPE tokens of the raw log, extracts the exact invoice failure on line 223, and returns a 92-token summary to the main agent.

3. Build, test, and validate Piece 2 in Python

#!/usr/bin/env python3
"""piece2_retrieve_offload_delegate.py: Offload large tool dumps & delegate reading to brick-v1-beta."""
import hashlib, json, math, os, ssl, urllib.request
from pathlib import Path

REGOLO_BASE_URL = os.environ.get("REGOLO_BASE_URL", "https://api.regolo.ai/v1")
OFFLOAD_DIR = Path(".harness/large_tool_results")
_SSL_CTX = ssl._create_unverified_context()

def _post_json(path: str, payload: dict, api_key: str) -> dict:
    req = urllib.request.Request(
        f"{REGOLO_BASE_URL}{path}",
        data=json.dumps(payload).encode("utf-8"),
        headers={"Authorization": f"Bearer {api_key}", "Content-Type": "application/json"},
        method="POST",
    )
    with urllib.request.urlopen(req, timeout=45, context=_SSL_CTX) as resp:
        return json.loads(resp.read().decode("utf-8"))

def offload_tool_output(tool_name: str, raw_output: str, max_chars: int = 1200) -> dict:
    if len(raw_output) <= max_chars:
        return {"offloaded": False, "context_payload": raw_output, "saved_path": None}
    OFFLOAD_DIR.mkdir(parents=True, exist_ok=True)
    digest = hashlib.sha1(raw_output.encode("utf-8")).hexdigest()[:10]
    file_path = OFFLOAD_DIR / f"{tool_name}_{digest}.txt"
    file_path.write_text(raw_output, encoding="utf-8")
    lines = raw_output.splitlines()
    preview = (
        f"[OFFLOADED: {len(raw_output)} chars, {len(lines)} lines at {file_path}]\n"
        f"HEAD:\n" + "\n".join(lines[:5]) + "\nTAIL:\n" + "\n".join(lines[-3:])
    )
    return {"offloaded": True, "saved_path": str(file_path), "context_payload": preview}

def delegate_chunk_analyst(file_path: str, question: str, api_key: str) -> dict:
    raw_text = Path(file_path).read_text(encoding="utf-8")
    resp = _post_json(
        "/chat/completions",
        {
            "model": "brick-v1-beta",
            "messages": [
                {"role": "system", "content": "Read the file and answer in at most 3 short bullet points citing exact line numbers and numbers."},
                {"role": "user", "content": f"Question: {question}\n\nFile ({file_path}):\n{raw_text}"},
            ],
            "max_tokens": 220,
            "temperature": 0.1,
            "chat_template_kwargs": {"enable_thinking": False},
        },
        api_key,
    )
    summary = (resp["choices"][0]["message"].get("content") or "").strip()
    return {"served_by_model": resp.get("model"), "distilled_summary": summary}

def handle_rpc(req: dict) -> dict | None:
    method, req_id = req.get("method"), req.get("id")
    if method == "initialize":
        return {"jsonrpc": "2.0", "id": req_id, "result": {"protocolVersion": "2024-11-05", "capabilities": {"tools": {}}, "serverInfo": {"name": "regolo-context-harness", "version": "1.0.0"}}}
    if method == "tools/list":
        return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": TOOLS}}
    if method == "tools/call":
        args = req.get("params", {}).get("arguments", {})
        api_key = os.environ.get("REGOLO_API_KEY", "")
        off = offload_tool_output(args["tool_name"], args["raw_output"])

            out = json.dumps({"offload": off, "subagent_answer": sub}, indent=2)
        else:
            out = json.dumps(off, indent=2)
        return {"jsonrpc": "2.0", "id": req_id, "result": {"content": [{"type": "text", "text": out}]}}
    return None

if __name__ == "__main__":

Frequently asked questions

What is the retrieve, offload, delegate pattern in agent context engineering?
Instead of dumping raw search results or large tool outputs straight into the main agent’s window, the harness saves oversized outputs to disk, returns only the file path and a short preview, and delegates reading the full file to a lightweight subagent.

When should an agent use grep instead of vector search?
When the agent knows the exact symbol, error code, or filename, literal filesystem search via glob and grep is faster and more precise. Semantic search with Qwen3-Embedding-8B is best when matching concepts phrased in different words.

Why shouldn’t my harness simply truncate large tool outputs?
Hard truncation permanently deletes lines in the middle of a log or data export where the critical error often sits. Offloading writes the complete payload to a local file so a subagent or paged read can inspect any line on demand.

Which model on our API runs the delegated chunk-analyst subagent?
Passing model="brick-v1-beta" routes routine chunk-reading turns to compact models in our pool such as qwen3.5-9b, which is priced at €0.00 during the beta (and included in our flat Core subscription) while keeping your primary reasoning agent’s context clean.

How does Piece 2 relate to context-mode and headroom?
